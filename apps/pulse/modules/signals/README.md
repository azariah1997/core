# signals

Private custom touch-pattern storage (spec §19-20): the "private touch language" differentiator - a bounded sequence of tap/hold/pause segments whose meaning exists only between two people. The platform never interprets semantic meaning, only stores and relays the pattern.

**Owns:** `custom_signals` table - each row bound to exactly one specific connection (spec §19's own example: the same `••` pattern means "I love you" for one pair and "I'm home" for another, so a saved pattern only ever means one thing: the relationship it was created for). Segment count and total/per-segment duration are server-enforced bounds at creation time (Architecture Audit Risk #4: max 20 segments, 20-3000ms each, 10000ms total) - an unbounded pattern is a real abuse vector (very long/rapid vibration), never merely a client-side UI limit.
**Depends on:** Core `relationships` directly (own `CoreRelationships` adapter, same shape as pulse-interactions' own) - a signal can only be created against a real, active Friend or Bond connection, checked the identical way every other interaction in this codebase checks it.
**Owns CRUD only - sending is pulse-interactions' job:** `POST/GET /v1/pulse/signals`, `GET/DELETE /v1/pulse/signals/{id}` manage the saved pattern *library*. Actually delivering a signal (felt live if the receiver is connected, durable push otherwise) reuses pulse-interactions' exact Create+Start+Stop state machine as a fourth `Type` (`TypeSignal`, `POST /v1/pulse/signals/{id}/send`) - the same reuse Knock established in Phase 7, rather than duplicating authorization/rate-limiting/delivery logic. `signals.Service.Get`'s own ownership check (only the pattern's real owner may resolve it) is pulse-interactions' entire authorization surface for sending - it never re-checks ownership itself, and the receiver is always the signal's own bound target, never a client-supplied value.
**Status:** implemented - Phase 11 (Custom Touch Language). Live-validated end to end with real Keycloak users (the Phase 9/10 sample connections, Alice → Bob): creating a real pattern, a real 403 rejecting a stranger's read of someone else's private signal, real bounds rejecting an oversized segment count and an out-of-range segment duration, a real push-fallback delivery landing in Core's database, and a real WebSocket round trip confirming the receiver's device gets the actual segments array live (via pulse-interactions' `signal.started` event) for local haptic playback - the whole point of "the pattern itself is the communication." Mobile ships a real Signals screen per connection: compose (with local preview via the real device haptics), save, send, and delete. Real source in `apps/pulse/api/internal/signals/`.
